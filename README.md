# AetherOS

Aether 官网的用户脚本：把同一水鱼账号下的多个角色放进一个桌面，保留官方界面与手动操作。也提供原页面可用的背包筛选和装备置顶。

## 安装

[安装 AetherOS](https://raw.githubusercontent.com/de3BDJMH/AetherOS/main/AetherOS.user.js) · [版本记录](https://github.com/de3BDJMH/AetherOS/releases)

- 电脑：先安装 Tampermonkey，再打开上面的安装链接，确认安装。
- iPad / iPhone：安装 Safari 的 Userscripts 扩展并启用，打开安装链接，从 Safari 扩展菜单进入 Userscripts，确认安装；允许脚本在 Aether 官网运行。
- 登录 [Aether 官网](https://game.diving-fish.com/aether/)，刷新后点击官网顶部导航栏的“多角色同屏”。背包筛选无需进入桌面即可使用。

从旧版升级需要先手动安装一次本版。脚本识别名称仍为“Aether 多角色同屏”，保留原 namespace，方便覆盖旧版。若之前安装的名称已乱码，请停用旧脚本，避免重复运行。

## 功能

- 自由打开角色窗口，拖动、缩放、重叠、最小化和最大化；窗口各自调整页面缩放比例。
- 底部头像任务栏，支持分屏贴靠、九宫格、边缘吸附，保存窗口布局。
- 官方“设置 → AetherOS”提供“隐藏左侧空闲黑屏”开关，默认开启，普通页面和多角色窗口共用并自动保存；剧情与战斗播放保留。数据同步和检查更新也集中在此子页。
- 装备按名称、部位、星级、元素筛选，支持按单件装备置顶；消耗品按技能书、光谱、其他分类并筛选。材料页保持原样。
- 筛选复用官网已加载的背包数据，不额外查询游戏接口；官网分页、提示和手动操作继续使用。
- 背包强化列表每页显示 30 件，支持名称、部位、星级、元素筛选，沿用普通背包与云端的装备置顶，置顶在分页前优先排序；减少重复强化时的装备行重绘。强化接口、连续强化和免费券继续由官网处理；已装备页保持原样。

强化详情下的“强化记录”会从官网当前失败次数接续，保存每一级第几次成功、成功时间和已记录的材料/用券次数。记录按角色与装备唯一标识保存在当前浏览器，穿脱或刷新后保留；连接数据同步后，强化记录也会自动合并同步到 Web，可在“角色管理 → 强化历史”中查询。首次同步方式只影响置顶，不会覆盖或删除强化历史。之前已经成功但没有记录的等级无法补回，网络结果不明确时等待重新选择装备后核对，不猜次数。

装备较多时，在“设置 → AetherOS → 数据同步”使用“读取当前角色／读取全部角色”。每个角色只查询一次状态，按装备标识合并背包与穿戴，导入已强化装备的当前等级与失败次数；原有历史保留，连接后同步到 Web。不会执行强化，也不能补回过去未记录的成功次数。批量读取支持停止，登录失效或限流会停止后续请求。

强化优化作用于官网返回的渲染列表，首次进入页面仍可能有原始列表的挂载开销。父组件构建完整列表和官网状态请求也继续存在。详见[排查与验证记录](docs/reinforcement-performance.md)。

## 分解页面

保留官网整页铺开的星级分组、全选、取消选择、收益预览和确认清单。选中标记改为卡片角落的浮动勾选，不改变卡片宽度，减少长列表重新排版。普通装备提示明确标注“装备”时，光谱等级逻辑直接跳过组件树查找；其他光谱提示继续沿用原识别。

星级分组继续使用官网已有的计算缓存。官网全量挂载和选择时逐项计算的开销仍然存在，本版不替换分解数据或选择逻辑，不增加 DOM 观察器、轮询或游戏请求。

隔离验证复用当前官网编译的 `DecomposerPanel`、`ItemChip`、Vue 3.5.26，以及模拟装备和收益预览；Vuetify 容器使用测试替身。2000 件测试装备保持全部显示，普通装备提示的光谱后备遍历由 30245 个节点降至 0；使用官网相关样式和图标字体，示例单次勾选的位置变化由 333 张降至 0。这些是模拟场景的工作量和布局计数，不代表真实设备的耗时。

## 装备比较

背包装备的鼠标悬浮提示、手机点击后的物品详情均增加四列差值：双方 +0、双方按身上装备强化等级、双方按背包装备强化等级，以及各自当前等级。以身上同部位装备为基准，高绿低红，百分比使用 `%`，属性图标与颜色沿用官网。亲和差值相同的元素并排合为一组图标，例外独立显示。没有穿戴时以空槽为基准；已穿戴的同一件装备不重复比较。只列出装备属性和亲和本身的数值，不替代整套角色配装计算。

复用当前页面已加载的数据和背包已有的装备绑定，只在悬浮或点开详情时计算这一件与同部位装备，不读取或扫描全部背包，不发游戏请求、不新增 DOM 观察器或后台轮询。保留官网原属性、技能和说明。比较表位于标题下方，重复的官方数值行在比较期间隐藏，价格、技能和套装说明保留。整块提示按视口约束高度，长内容在内部滚动；定位外层不设滚动，避免被官网反复扣减宽度。

手机详情底部在分解、锁定、出售旁增加“置顶 / 取消置顶”，沿用背包已有的角色独立置顶和云同步；锁定的装备也可置顶。比较与置顶无需读取新的游戏数据。长详情只滚动内容区，底部操作保留；极窄屏的四个辅助按钮分成两行。

## 光谱等级提示

官网光谱槽位、背包光谱和光谱描述中的公式悬浮提示会附上各级效果表，已知当前等级会高亮。数值复用人工维护的 73 种光谱资料，动态效果显示亲和／面板对应的系数，原公式和触发说明保留。不可升级的光谱仅展示 Lv1；未收录的新光谱继续显示官网原提示。数据内置于脚本，不增加游戏请求，更新资料随脚本版本发布。

## 跨角色物品查找

官网背包标题旁的“查找物品”可以按名称、角色、分类、星级、元素和部位查找装备、技能书、光谱、材料与其他物品。点击“读取当前角色／全部角色”才读取官网库存，每个角色一次状态请求，批量按顺序执行并可停止；穿戴装备按唯一标识去重后计入。搜索只查缓存，结果显示各角色数量、穿戴数量和读取时间，每页 20 种。

连接现有数据同步后，手动读取的库存可与 Mugen-Web“角色管理 → 物品查找”共用；打开查找窗口或点击“同步缓存”可取回 Web 已读取的快照。库存以每个角色较新的整份快照为准，多台设备不会重复累计数量。失败或停止保留旧缓存。消耗或获得物品后需要手动重读，不自动刷新库存。

星级、元素和部位支持多选，同组按“或”匹配，不同组叠加筛选。元素复用原背包的属性、亲和和技能资料判断；旧库存仍保留，重新读取后才具有元素信息。多设备请一起更新到 0.24.0，以读取新版库存快照。

不新增全局 DOM 监听、请求拦截或库存轮询；不会恢复已回退的装备占用提示和分解分页。

## 数据同步

官网“设置 → AetherOS → 数据同步”和桌面角色菜单使用同一个入口，原“置顶云同步”入口已更名。

- **同步概览**：分别显示装备置顶、助战置顶、强化记录、装备预设、账号排序与备注、物品库存的状态；点开一行查看详情。已连接时默认打开此页。
- **读取强化**：手动读取当前／全部角色的强化进度，保留停止读取；打开此页不请求角色数据。
- **连接管理**：粘贴设备码、选择首次装备置顶处理方式、更换连接或断开本机；未连接时默认打开此页。

概览的“立即同步”包括已有库存缓存，不会刷新游戏官网库存；最新库存仍需在“物品查找”中手动读取。

1. 更新 Mugen-Web 后，通过手机也能访问的 HTTPS 地址打开后台，在 Aether 控制台进入“运行设置 → 设备与同步 → 装备置顶”。
2. 每台设备分别生成一个设备同步码，在游戏官网“设置 → AetherOS → 数据同步”中粘贴。地址已经包含在码中，不需要手动填写。
3. 首次选择“合并本机与云端”“本机已有角色为准”或“使用云端置顶”。本机优先只覆盖本机已有角色。
4. 以后置顶或取消置顶自动逐项同步；断网时保留队列，联网后补同步。窗口布局、缩放和筛选保持各设备独立。

同步需要支持 Web Locks 的现代浏览器。同一装备的不同操作按服务器接收顺序处理；重复请求不会重新应用旧操作。可以在网页后台撤销设备；断开同步不会删除本机置顶。设备码授予装备置顶、强化记录、自定义预设、账号与好友偏好及手动库存快照的同步权限，不是后台密码，也不能操作 Bot 或读取游戏登录信息。

每日强化选择读取同一份云端置顶，置顶装备排在最前面；返回网页窗口时会重新读取置顶，不改变已选装备或自动保存配置。尚未启用云同步的本机置顶不会凭空出现在每日页面。

服务端使用 Mugen-Web 自己的 `data/aether/pin_sync.sqlite3`，只存置顶、设备授权摘要和同步序号，不访问 Bot 数据目录。强化历史单独保存在 `data/aether/reinforce_history.sqlite3`。库存快照单独保存在 `data/aether/inventory.sqlite3`。迁移时停止 Web 后将这些文件一起搬迁；域名不变可保留设备绑定，域名改变后重新生成码连接。

## 强化助手

选择装备后，原材料数量旁显示“期望≈… · 至多…”，估算从当前等级到下一级的消耗，已计入当前失败次数和保底进度，并分别显示对应剩余材料；剩余为负数时标红，零不标红。按接口返回的当前成功率与保底规则计算；没有有限保底时会明确标注。

勾选官网的免费强化券后，可设置“最多使用几张”（默认 1 张），点击“连续用券”开始。成功即停，两次请求至少间隔 0.5 秒，并等待上次结果和官网信息刷新；如果官网动画或网络更慢，会继续等待，不并发提交。只使用券，券不足不会改用材料。

运行时有独立停止按钮。停止不会撤回已经发送的那一次请求；遇到网络异常或结果无法确认会停止，不自动重试，应先检查本次结果。切换装备、角色或离开强化页后不再继续。页面刷新不会自动恢复用券。仅提取装备标识、名称、强化进度、次数和时间用于记录；不保存完整响应、角色面板或认证凭证。

## 更新

版本和安装文件均由本仓库提供。成功检查后 24 小时内不重复请求，失败后至少间隔 1 小时自动重试；只在外层页面检查，不让每个角色窗口重复请求。发现新版会提示“更新脚本”，点击后由脚本管理器确认安装，安装完成再刷新官网。

官网右侧导航按钮组的最左边提供“多角色同屏”和“检查更新”，无需进入桌面即可使用；窄屏显示为刷新箭头图标。桌面左下角角色菜单仍提供“检查更新”和当前版本号。电脑脚本管理器也可通过 `@updateURL`、`@downloadURL` 检查更新。iOS 扩展支持情况不同时，仍可使用脚本内提示和安装链接。

检查只匿名读取公开版本信息，不发送游戏 Cookie、账号令牌或角色资料，不会自动执行下载的代码，也不会为更新刷新游戏。

## 范围

脚本适用于一个水鱼账号下的多个 Aether 角色，不提供多个独立水鱼账号的登录隔离。装备穿戴、战斗和领取继续由你手动操作；连续用券需要主动点击启动，按数量上限执行。桌面会增加浏览器资源占用，按需打开角色即可。

本地仅保存窗口设置、角色用户名、背包筛选、置顶装备 UUID、强化记录和同步／更新状态。不需要 Mugen Bot，也不需要内部 API key。官方页面结构变动后可能需要适配。

## 维护与测试

```sh
python tools/release.py
python tools/release.py --check
node --check AetherOS.user.js
```
